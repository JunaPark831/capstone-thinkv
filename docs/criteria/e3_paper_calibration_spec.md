# 논문 캘리브레이션 재현 명세 (Algorithm 1) — 사전 기록

- 작성 시각: 2026-11-04 (이 명세로 만든 결과를 보기 전)
- 원칙: 논문(ThinKV, arXiv 2510.01290v2) Algorithm 1을 **그대로** 따른다. 논문에 없거나 애매한 것은 사용자에게 묻고 여기에 기록한다. 결과를 본 뒤 이 명세를 고치지 않는다.
- 이 문서는 `docs/criteria/e3_paper_exact_criteria.md`, `docs/criteria/e3_denominator_variants.md`의 측정 실험(탐색)과 별개로, **본 캘리브레이션**의 명세다.

## 1. 논문이 정한 것 (그대로 따른다)

출처: Algorithm 1(Appendix D.1), §4.1 Offline Calibration / Decode-Time Behavior, §6.1 Hyperparameters, Appendix C.2, E.3.

1. 입력: 사전학습 모델, 캘리브레이션 프롬프트 P개, 사고 유형 수 `T=3`.
2. 캘리브레이션 데이터: **s1K에서 무작위 100개 프롬프트**(§6.1). `P=100`.
3. 각 프롬프트를 모델로 생성하고(Alg. 5행), **매 디코드 스텝 t, 모든 레이어 ℓ**에서 희소도 u를 구해 `U_ℓ[p][t]`에 쌓는다(7~9행).
4. 희소도 u: 정규화된 어텐션 `softmax(qKᵀ)`에서 **행 최댓값의 1% 미만인 위치의 비율**(본문 각주 2).
   - GQA(Appendix C.2, 식 2–4): 그룹 안 쿼리 헤드의 softmax 전 점수 `a_{h,g}=q_{h,g}K_hᵀ/√d`를 헤드에 걸쳐 **max pooling**(식 3), 그 결과에 **softmax**(식 4). 희소도 분석에서는 그룹에 걸쳐 어텐션 점수를 **평균**한다.
5. 프롬프트별·레이어별로 `U_ℓ[p]`에 KDE `f̂_h(x)=1/(Mh) Σ K((x−x_m)/h)`를 적용한다(17행).
6. 모드 `Ω = {x | f̂'(x)=0, f̂''(x)<0}`(18행). `|Ω|=T`이면 그 프롬프트의 `L*[p]`에 ℓ을 넣는다(19~21행).
7. `L* = ∩_p L*[p]` — **모든 프롬프트의 교집합**(24행).
8. `ℓ∈L*`, 프롬프트 p마다 KDE의 **모드 사이 국소 최솟값**을 임계값 `θ^{(ℓ,p)}_1..θ^{(ℓ,p)}_{T−1}`로 기록(27행). 최종 `θ_j = L*와 P에 걸친 평균`(30행).
9. 디코드 시: L* 레이어들의 희소도 평균을 θ와 비교해 유형을 정한다. 갱신 간격 τ=128스텝(§4.1). 하이퍼파라미터 `|L*|=4`, τ=128(§6.1).
10. 유형 이름 대응(E.3, 그림 3): 희소도가 낮은 쪽이 Execution, 중간이 Reasoning, 가장 높은 쪽이 Transition.
11. 최대 생성 길이 32K 토큰(§6.1 평가 설정, Cai et al. 2025를 따름).

## 3. 논문에 없어 우리가 기본값으로 정한 것 (이의가 있으면 바꾼다. 결과 전에)

- 생성 샘플링: temperature 0.6, top-p 0.95, 프롬프트마다 `torch.manual_seed(0)`. 논문에 샘플링 설정이 없다(0건 확인). 프롬프트 형식은 채팅 템플릿 + `\nPlease reason step by step, and put your final answer within \boxed{}.`.
- 프롬프트 선택: `simplescaling/s1K-1.1`의 train **전체 1000문제**에서 `shuffle(seed=0)`으로 앞 100개. (논문 인용은 s1K이고 1.1은 같은 문제에 추론 궤적만 다르다. 우리는 모델이 직접 생성하므로 궤적은 쓰지 않는다.) 이전 실험의 수학 877문제 한정과 다르다.
- 최대 생성 길이: 32768토큰(논문은 "32K"라고만).
- 어텐션: eager(가중치를 읽으려면 필요). 논문의 HF 코드는 FlashAttention-2가 기본이라 점수가 안 나오므로, 논문이 점수를 어떻게 얻었는지는 밝히지 않았다.
- KDE는 워밍업을 포함한 **모든 디코드 스텝**에 적용한다. 평가 격자 `[0,1]` 512점. 모드 = 격자의 내부 국소 극대(`scipy.signal.find_peaks`, prominence 없음), 모드 사이 골 = 연속한 두 모드 사이 KDE 최솟값.
- 점수는 모델 dtype(bf16)으로 `q·Kᵀ·scaling`을 계산한 뒤 fp32로 올려 softmax한다.
- 3개 임계값 이름 대응은 10번 그대로.

### 우리 해석이 들어간 부분 (플래그)

1. **첫 토큰 제외를 세 변형 모두에 일관 적용한다.** 사용자는 "행 전체에서는 첫 토큰을 뺀다"고만 말씀하셨다. 창 변형(1024, 256)은 위치 1..n−1 중 최근 W개로 정의한다. 이전 탐색의 창 변형은 n ≤ W일 때 첫 토큰을 포함해 n≈W에서 수준이 꺾였는데, 이 정의에서는 그 꺾임이 생기지 않는다. 사용자가 다르게 원하면 바꾼다.
2. **문자 그대로의 행 전체(첫 토큰 포함)도 참고 변형 `full_literal`로 함께 저장한다.** 같은 패스에서 계산하므로 추가 비용이 없다. 임계값·L* 산출의 주 변형이 아니고, Algorithm 1을 돌려 참고로만 기록한다.
3. 위치 0은 채팅 템플릿이 붙이는 BOS 토큰이다.

## 4. 변형 정의 (모두 같은 집계, 위치 집합만 다름)

디코드 스텝(쿼리 길이 1)마다 레이어별로, 그룹별 softmax 전 점수를 쿼리 헤드에 걸쳐 max pooling → **위치 집합에 대해 softmax 재정규화** → 그룹 평균으로 행 하나 → 그 행에서 `< 0.01·max` 비율.

| 이름 | 위치 집합 |
|---|---|
| `full_nosink` | 1..n−1 |
| `win1024` | 1..n−1 중 최근 1024개 |
| `win256` | 1..n−1 중 최근 256개 |
| `full_literal` (참고) | 0..n−1 |
| `sink_mass` (진단) | 희소도가 아니다. 모델이 낸 헤드별 softmax 가중치 중 위치 0의 확률을 헤드 평균 |

## 5. 판정 규칙

- 변형 ①②③을 각각 독립적으로 Algorithm 1에 넣는다(변형별 L*와 θ).
- **성공:** 교집합 `L*`가 비어 있지 않다. 그러면 L*의 θ₁, θ₂를 산출한다. `|L*|=4` 요건은 쓰지 않는다(사용자 결정). L* 크기가 논문의 4와 다르면 그 사실을 함께 보고한다.
- **실패:** 교집합이 공집합이다. 이 경우 임의로 완화하지 않고 **멈춘 뒤 사용자에게 보고하고 방향을 다시 묻는다.** 이 명세는 결과를 본 뒤 바꾸지 않는다.
- 항상 보고: 레이어별로 정확히 3봉인 프롬프트 수(교집합이 비어도), 프롬프트·레이어 봉우리 수 분포, EOS로 끝난 프롬프트와 32768 상한에서 잘린 프롬프트 수, 참고 변형 `full_literal`의 같은 결과.
- 교집합이 "모든 100개 프롬프트에서 정확히 3봉"을 요구하므로, 잔물결로 우연히 통과할 확률은 매우 작다. 통과하면 우연보다 구조일 가능성이 크지만, 구조 없는 기준선에서 같은 규칙이 비어 있는지를 음성 대조로 함께 보고한다(`full_literal`).

## 6. 실행 계획과 비용

- 산출: 문제마다 `{idx:04d}.pt` (희소도 `(5, 32, steps)` fp16 + `token_ids` + 메타). 이미 있으면 건너뛰므로 중간에 멈춰도 이어서 가능하고 `--shard i/N`으로 나눠 돌릴 수 있다.
- 규모: 100개 × 최대 32768토큰. 이전 Llama-8B/AIME 평균 생성 길이 약 13.5k를 가정하면 약 135만 토큰이다. 이 Mac의 측정 속도(초당 약 7토큰)로는 약 2~3일이다. GPU에서의 속도는 아직 측정하지 않았다.
- GPU 요건(추정): Llama-8B bf16 가중치 약 16GB + 32K KV 캐시 약 4.3GB + 활성값 → 24GB는 빠듯하고 40GB 이상을 권장한다. 한 GPU에 프로세스를 여러 개 띄우는 샤딩이 처리량에 도움이 될 수 있다.
- 환경: `transformers==5.2.0`(어텐션 등록 API가 이 버전 기준), `torch`, `datasets`, `scipy`, `tqdm`.

## 7. 알려진 한계

- 논문이 정의를 정하지 않은 부분(KV 위치 범위, KDE 폭)의 선택이 결과를 좌우한다. 위 3절·4절에 모두 적었다.

```bash

# 샤딩(한 GPU에 여러 프로세스 / 여러 세션): --shard 0/3, 1/3, 2/3 를 각각 실행. 이미 있는 파일은 건너뛴다
python calib/paper_calibration/calibrate_paper.py --dir calib/sparsity/s1k_llama8b_p100_max32768 --variant full_nosink --out OUT.json
```

## 검증한 것

1. `calibrate_paper.py --selftest`: 합성 3수준 데이터(0.45/0.70/0.90)에서 L*가 기대한 [0,1,2]로 나오고 θ = [0.575, 0.800](골 위치). 한 프롬프트에서 레이어 하나를 1봉으로 망가뜨리면 교집합에서 빠진다.
2. 수집 스크립트를 Llama-8B로 실제 생성(P=1, 400토큰, MPS, 초당 9.6토큰)해 돌린 뒤, 같은 토큰을 이전 재생 스크립트(별도 경로)로 다시 재서 대조: `full_nosink`, `full_literal`, `sink_mass`, `win256`(n>256 구간)이 모두 **최대 절대 차이 0**. 창 변형은 n이 W 이하일 때 `full_nosink`와 같다(첫 토큰을 일관 제외한 정의가 의도대로 동작).
3. 기존 두 궤적(P=2)으로 Algorithm 1 코드 경로를 리허설했다. **이 숫자는 결과가 아니다**: P=2에서는 레이어 하나가 두 프롬프트에서 우연히 정확히 3봉일 수 있다(P=100에서는 교집합이 거의 우연으로 생기지 않는다).

## 리허설에서 드러난 미결 사항 (사용자에게 질문함)

KDE에 **모든 디코드 스텝(워밍업 포함)**을 쓰는 것이 논문 문자 그대로(Alg. 6행)이지만, 우리 측정에서는 앞쪽 스텝이 길이와 함께 오르는 구간이라 결과가 크게 달라졌다(P=2 리허설, 의미 없는 값으로 영향의 크기만 본다): `win1024`의 L*가 [25, 29]에서 [11, 14, 29]로, θ가 [0.745, 0.926]에서 [0.514, 0.604]로 바뀌었고 `full_nosink`는 L*가 비었다. 수집은 모든 스텝을 저장하므로 이 규칙은 수집과 무관하게 나중에 정할 수 있고, 옵션 `--skip-first N`(기본 0 = 문자 그대로)으로 바꾼다.

## 논문 Algorithm 1 대 우리 구현 대조 (2026-11-04, 사용자 질문 "봉우리·경계값이 논문 공식 그대로인가")

출처: arXiv 2510.01290 본문 4.1 "Offline Calibration"과 부록 D.1 Algorithm 1 (17~30행). 내려받은 본문 추출본에서 18행 `f''(x)` 뒤가 잘려 있어 부등호는 보이지 않는다(표준 정의 f''<0으로 구현).

| 논문 | 우리 구현 (`calibrate_paper.py`) | 일치 |
|---|---|---|
| 17행: 문제 p·레이어 ℓ마다 모든 디코드 스텝의 희소도에 KDE | 문제·레이어마다 모든 스텝(`skip=0`)의 시계열에 KDE | 같음 |
| KDE 커널 K, 폭 h | **논문이 정하지 않음.** 가우시안, scipy 기본 폭 Scott ×1 (사용자 지시) | 우리 선택 |
| 18행: f'(x)=0 이고 f''(x)<0 인 점을 모드로 | 0~1을 512점 격자로 나눠 `find_peaks`로 국소 최댓값(옵션 없음, prominence 없음) | 근사 구현 |
| 19~21행: 모드 수가 T(=3)인 레이어를 L*[p]에 | 동일 | 같음 |
| 24행: L* = 모든 문제의 교집합 | 동일 | 같음 |
| 27행·본문: 모드 사이의 국소 최솟값 = 임계값 | 이웃한 두 모드 사이 KDE의 최솟값 위치 (모드 3개면 골 2개) | 같음 |
| 30행: θ_j = (ℓ∈L*, 문제 p) 전체 평균 | 동일 | 같음 |
| 입력 ℓ*(최적 레이어 수)를 어떻게 맞추는지 | 논문이 정하지 않음. 교집합 전체를 쓰고 비면 FAIL (사용자 결정) | 우리 선택 |

- 수치 구현의 한계: 격자 양 끝(x=0, x=1)의 봉우리는 `find_peaks`가 세지 못한다. P=9 데이터에서 x=1에서 KDE가 아직 올라가는(끝 봉우리로 의심되는) 시계열은 `full_nosink` 2, `win1024` 0, `win256` 0, `full_literal` 53개(각 288개 중)이고, x=0 쪽은 각각 4, 4, 1, 8개다. 주 변형 세 개에서는 영향이 작고, `full_literal`에서는 봉우리 수가 과소 계산될 수 있다. 이 때문에 위 FAIL 판정이 뒤집히지는 않는다(봉우리가 더 많이 세어진 쪽이 문제이므로).
- 입력 시계열 자체(어느 KV 위치로 재는가, 위치 0 제외, 창)는 위 식 2~4가 아니라 측정 쪽 선택이다. 논문 문자 그대로에 가장 가까운 것은 `full_literal`이고, 나머지는 사용자가 고른 변형이다.

## "봉우리다운 것만" 사전 기록 (2026-11-04, 사용자 지시 "좀 더 봉우리다운 거만 남겨보자", 계산 전에 작성)

- **엄격도 단계:** 기준(prominence 0.02) → L1(0.02, 거리 0.05, 골 깊이 0.15) → **L2(0.05, 0.05, 0.30, 주 단계)** → L3(0.05, 0.10, 0.50). 결과를 보고 단계 값을 바꾸지 않는다.
- **조합:** Scott ×0.5(주, 직전 지시를 이어감)와 ×1(병기), 변형 `win256`·`win1024`, 워밍업 전체(주)와 앞 1100 제외(병기), P=9. 앞선 규칙대로 변형 단위(봉우리 수 합이 큰 쪽)와 레이어 단위 선택을 보고한다. 보고: 봉우리 수 분포, 정확히 3봉인 시계열 수, 레이어별 정확히 3봉인 문제 수의 최댓값, L*(비면 FAIL), 2/3 규칙, 모든 문제에서 봉우리 수가 같은 k≥2 레이어.
- **미리 밝히는 기대(결과 아님):** 엄격할수록 봉우리가 줄어 대부분 1봉이 되고, 남는다면 `win256` 레이어 0 정도일 것으로 예상한다. 단계 값은 임의의 선택이므로 단계 전체를 보고한다.
- **해석 규칙(미리):** L*가 생기면 문제별 히스토그램을 그려 눈으로 확인한 뒤 사용자에게 판단을 묻는다. L*가 비면 FAIL로 기록하고 논문 문자 그대로의 판정은 바뀌지 않는다.

## 키워드 라벨 신호 검증 사전 기록 (2026-11-04, 사용자 지시 "희소도에 사고 유형 신호가 조금이라도 있나 확인", 계산 전에 작성)

- **목적:** 지금까지는 비지도로 봉우리만 찾았다. 이번에는 논문 부록 D.2 표 7의 키워드로 디코드 스텝에 사고 유형 라벨을 붙이고, **라벨별로 희소도 분포가 갈리는지**를 본다. 키워드는 **검증용 라벨**이며 추론 분류기가 아니다(사용자의 "희소도 측정으로만" 결정과 충돌하지 않도록 명시). 논문도 키워드를 "해석용"으로만 쓴다고 적었다.
- **라벨 규칙(내 선택):** 저장된 `token_ids`를 토큰 단위로 디코딩해 문자 위치 → 토큰 인덱스로 대응시킨다. 키워드(대소문자 무시, 단어 경계, 긴 구절 우선): Transition = {wait no, but wait, earlier i said that, wait, hmm, alternatively}, Reasoning = {think, approach, remember, find, okay, suppose, verify}, Execution = {now, the steps are}. 키워드가 나온 토큰 k부터 **W=64** 토큰 동안 그 유형으로 라벨하고, 그 안에 다른 키워드가 나오면 거기서 새 라벨로 바뀐다. 나머지는 미라벨. 보조안 B: 미라벨 중 `=`, `\boxed`, `\frac`가 있는 줄의 토큰을 Execution(수식)으로 추가. 민감도: W=32, 128도 출력.
- **정렬:** `sparsity[:, :, s]`는 쿼리 토큰 `ids[s]`를 처리할 때 잰 값(prefill 제외, 길이 n−1)이므로 토큰 인덱스 라벨을 그대로 `s`에 쓴다.
- **측정:** 변형 `win1024`(주), `win256`, `full_nosink`의 레이어별 원시 희소도. 라벨 쌍 (T vs E), (R vs E), (T vs R)의 AUC(Mann–Whitney). 논문 방향은 E < R < T(실행이 가장 희소도 낮음, 전환이 가장 높음). (a) 문제 합친 AUC, (b) 문제별 AUC의 중앙값(문제마다 두 라벨이 20스텝 이상일 때). **위치 대조:** 문제별로 1025스텝 이동평균을 뺀 잔차로 같은 AUC를 다시 계산한다(희소도가 글 위치에 따라 오르는 효과를 제거).
- **통과 기준(gate):** `win1024`, 안 A, W=64에서 **T vs E 합친 AUC ≥ 0.65(논문 방향)인 레이어가 4개 이상**이고 그 레이어들의 문제별 AUC 중앙값 ≥ 0.60이면 "신호 있음". AUC ≤ 0.35인 레이어가 4개 이상이면 "신호 있음, 방향 반대"로 따로 적는다. 잔차 AUC가 0.55 미만이면 "위치로 설명될 가능성"을 표시한다(gate는 원시 AUC로 정한다).
- **보고:** 키워드별 적중 수, 문제별 라벨 스텝 수, 레이어별 AUC 표와 그림, 가장 좋은 4개 레이어의 라벨별 히스토그램. 기준 미달이어도 모든 수치를 보고한다.

## 문턱 1% → 2·5·10% 재측정 사전 기록 (2026-11-04, 사용자 지시 "5%로 올리면 결과가 다르지 않을까", 계산 전에 작성)

## 문제 전체 합친(pooled) 분포의 3봉 확인 사전 기록 (2026-11-04, 사용자 지시 "모든 문제를 다 합쳐서 봉우리가 3개로 명확한 경우 확인", 계산 전에 작성)

- **방법:** 레이어마다 9개 문제의 희소도 시계열을 **이어 붙여** 하나의 분포로 만들고 KDE(가우시안, Scott ×1, 512점 격자)를 구한다. Algorithm 1은 문제별 KDE의 교집합이므로 이는 논문에서 벗어난 완화다. 채널: 재생값 17채널(변형 4 × 문턱 4 + sink_mass) 중 희소도 16채널. 워밍업: 전체 스텝(주)과 앞 1100 제외(병기).
- **봉우리 세기:** 필터 없음(논문 글자 그대로)과 **봉우리다움 L2**(prominence 0.05, 거리 0.05, 골 깊이 0.30; 앞서 정의) 둘 다 보고. 합친 n이 약 13만이라 Scott 폭이 좁아져 요철이 많아지므로 판정은 L2로 한다.
- **합침 때문에 생기는 가짜 봉우리 점검(미리 정함):** L2 봉우리가 2개 이상인 레이어마다 각 스텝을 골 기준으로 봉우리 구역(basin)에 배정하고, 구역마다 (a) 문제별 구성 비율, (b) 글 내 위치(0~1) 중앙값, (c) 키워드 라벨(안 A, W=64) 구성을 센다. 어떤 구역이 **한 문제에서 70% 이상** 오면 "문제 간 수준 차이", 구역의 위치 중앙값이 **0.10 미만**이면 "초반 상승 구간"으로 표시한다. 이런 구역이 포함된 3봉은 구조의 증거로 보지 않는다.
- **판정:** L2에서 정확히 3봉이고 위 표시가 하나도 없는 레이어가 있으면 "합친 분포에 3봉 후보 있음"으로 적고 그림으로 사용자에게 판단을 묻는다. 없으면 "합쳐도 3봉 없음". 어느 쪽이든 논문 그대로의 FAIL 판정은 바뀌지 않는다.
- **그림:** 주 채널(win1024@1, win256@1, full_nosink@1)과 3봉 후보가 나온 채널에 대해 32레이어 격자(문제별로 색을 나눈 누적 히스토그램 + 합친 KDE + L2 봉우리·골).

### 합친(pooled) 분포 3봉 확인 결과 (P=9, 위 사전 기록대로)

- 코드·산출물: `calib/paper_calibration/pooled_peaks.py`, `calib/paper_calibration/pooled_n9/` (`result.json`, `index.html` 갤러리, 주 채널 3개 × 워밍업 2가지의 32레이어 격자 그림; 막대는 문제별 색 누적).
- **16채널 × 워밍업 2가지 = 32조합 전부에서 봉우리다움 L2 기준 정확히 3봉인 레이어 0개.** 2봉 이상도 `win256@2`의 레이어 0 하나뿐(봉우리 0.50·0.73, 골 0.64; 문제 편중·초반 표시 없음). 이 레이어 0은 앞서 토큰 확인에서 숫자 대 기호·단어 토큰으로 갈린 그 레이어다.
- 필터 없이 세면 합친 n(약 13만)으로 Scott 폭이 좁아져 요철이 늘어난다(중앙값 1~39개). 그림에서 모든 레이어가 "왼쪽 긴 꼬리 + 봉우리 하나"이고, 문제별 색이 같은 위치에 겹쳐 쌓인다(문제 간 수준 차이로 생기는 봉우리도 없음).
- **결론:** 문제를 합쳐도 3봉은 없다. 논문 Algorithm 1(문제별 교집합)보다 훨씬 느슨한 조건에서도 구조가 나오지 않으므로, "문제 수가 적어서(교집합이 너무 엄격해서) 실패했다"는 설명은 이 데이터에서 성립하지 않는다.

## 위치 마스킹 + 누적 질량 정의 재측정 사전 기록 (2026-11-04, 사용자가 붙여 넣은 외부 제안 3·4번 적용, 계산 전에 작성)

- **제안 3(임계값 방식) 검토:** 우리 규칙은 절대값 0.01이 아니라 **행 최댓값 대비 1%**다. 부분집합 softmax에서 p_j/p_max = exp(s_j − s_max)이므로 이는 softmax 전 점수로 "s_j < s_max − ln 100"을 세는 것과 **동일**하다. 따라서 "raw score 기준"은 별도 계산 없이 동일 결과다. 새로 시험하는 것은 **누적 질량 정의**: 가중치를 내림차순으로 더해 전체의 90%(또는 95%)에 이르는 데 필요한 위치 수 k를 세고 희소도 = 1 − k/(위치 수).
- **제안 4(RoPE·위치 편향) 적용:** 싱크 블록(위치 0~3)과 로컬 창(쿼리 자신 포함 최근 8개 위치)을 희소도 계산에서 **제외**한 "mid" 범위를 추가한다. 범위 6개: `full_nosink`(1..g, 기존), `full_mid`(4..g−8), `win1024`(기존), `win1024_mid`(max(4, g−1023)..g−8), `win256`(기존), `win256_mid`(max(4, g−255)..g−8). 제외 폭 4와 8은 제안의 "첫 1~4개", "직전 5~10개"에서 내가 고른 값이다.
- **측정:** 범위 6 × 정의 4(`max1` 최댓값 대비 1%, `max5` 5%, `mass90`, `mass95`) = 24채널 + `sink_mass`. 식 2~4(max-pool → 범위 내 softmax 재정규화 → 그룹 평균)는 그대로. 청크 재생(`replay_masked.py`, Mac). 회귀: 기존 범위의 `max1`은 직전 재생(`s1k_llama8b_p15_thresholds`)의 1% 채널과 거의 같아야 한다(같은 청크 경로).
- **판정(채널마다, 기준 그대로):** 논문 그대로 Algorithm 1 L*, prominence 0.05 필터, 키워드 라벨 AUC gate(≥0.65 레이어 4개 + 문제별 중앙값 ≥0.60), 합친 분포 L2 3봉 점검.
- **미리 밝히는 기대(결과 아님):** 로컬 창을 빼면 행 최댓값이 바뀌어 희소도 값과 범위는 달라질 것이다. 사고 유형 신호가 생길지는 모르며, 키워드 AUC가 0.5 근처면 "위치 편향 제거로도 신호 없음"으로 적는다.
