# E3 가설 1 시험 — 분모(싱크·길이 희석) 변형, 사전 기준

- 작성 시각: 2026-11-04 (이 변형들의 결과를 보기 전)
- 선행 문서: `docs/e3_paper_exact_criteria.md` (논문 식 재측정, 결과 기록 포함). 그 문서와 이 문서의 기준은 결과를 본 뒤 고치지 않는다.
- 상태: 이 변형으로 계산한 값은 아직 하나도 보지 않았다.

## 1. 시험하는 가설

논문 식(`paper`)으로 재도 우리 희소도는 스텝과 함께 0.86에서 0.98로 오르며 포화한다(`paper` 레이어 10 기준 스텝 상관 0.69, 0.98 초과 비율 0.67). 논문 그림 3a의 띠는 컨텍스트 길이와 무관하게 수준이 고정돼 있다.

**가설 1:** 행 전체(프롬프트 포함, 첫 토큰 포함)를 분모로 쓰면 소수의 무거운 위치(어텐션 싱크 등)가 최댓값을 정하고, 1%를 넘는 위치 수는 길이에 거의 비례하지 않아 희소도가 `1 − (무거운 위치 수)/n`으로 1.0에 몰린다. 첫 토큰을 빼거나 최근 W개 위치만 보면 이 포화가 풀리고 수준이 길이와 무관해진다.

기존 관찰에서 이미 계산 가능한 진단(재생 불필요): 무거운 위치 수 `k(t) = (1 − s(t))·n(t)`, `n(t) = input_len + t + 1`. 이것은 §4의 보고 항목에 포함한다.

## 2. 변형 (같은 궤적 `0005.pt`를 teacher forcing으로 재생, 모든 변형을 한 패스에서 계산)

앞의 네 개는 직전 실험과 동일한 정의다(회귀 확인용). 새 변형은 모두 `paper`와 같은 집계(softmax 전 점수를 그룹 안 쿼리 헤드에 걸쳐 max pooling → **부분집합에 대해 softmax 재정규화** → 그룹 평균으로 행 하나 → 그 행에서 `< 0.01·max` 비율)를 쓰고, 행에 넣는 KV 위치 집합만 다르다. 희소도의 분모는 그 집합의 크기다.

| # | 이름 | KV 위치 집합 |
|---|---|---|
| 0~3 | `legacy_perhead`, `paper`, `pergroup_maxpool`, `headavg_nomax` | 직전과 동일 |
| 4 | `paper_nosink` | 위치 0(첫 토큰) 제외, 1..n−1 |
| 5 | `paper_win256` | 최근 256개 위치(n ≤ 256이면 전체) |
| 6 | `paper_win1024` | 최근 1024개 위치(n ≤ 1024이면 전체) |
| 7 | `sink_mass` | 희소도가 아니다. 모델이 낸 헤드별 softmax 가중치에서 위치 0이 받는 확률을 헤드에 걸쳐 평균한 값(진단용) |

- 창 변형은 n > W가 되면 위치 0을 자연히 제외한다. n ≤ W인 초반에는 싱크를 포함한다.
- 점수는 모델 dtype(bf16)으로 `q·Kᵀ·scaling`을 계산한 뒤 fp32로 올린다. 부분집합 선택은 그 뒤에 한다.
- W=256, 1024는 논문의 사고 구간 길이(100~300토큰, 갱신 간격 128)와 우리 궤적 길이(3301)를 고려한 두 점이다. 결과를 본 뒤 W를 바꾸지 않는다.

## 3. 판정 기준 (모두 `paper_nosink`, `paper_win256`, `paper_win1024`에 대해 변형별로 보고)

스텝 ≥ 1100만 쓴다(두 창이 모두 찬 뒤, 초반 워밍업 제외). 128스텝 이동평균을 MA라 한다.

- **S1 포화 해소:** 레이어별 `frac(sparsity > 0.98) < 0.20`인 레이어 수. 8개 이상이면 "포화 해소됨".
- **S2 길이 독립:** S1을 만족한 레이어 중 `|corr(step, sparsity)| < 0.30`인 레이어 수. S1 만족 레이어의 절반 이상이면 "길이 독립".
- **S3 띠 구조:** 직전 문서 §6 기준 그대로. Scott ×0.5/×1/×2 세 폭 모두에서 `find_peaks`(prominence 없음) 봉우리가 정확히 3개인 레이어가 4개 이상. 보조로 `prominence=0.05` 정의도 기록한다. 이 분석은 전체 스텝이 아니라 **스텝 ≥ 1100**에 적용한다.
- **D 변동폭(참고):** 레이어별 MA의 5~95 퍼센타일 폭. 논문 그림 3a의 띠는 폭이 0.45 이상이다(눈금 읽기, 근거 약함). 참고로만 보고하고 판정에는 쓰지 않는다.

| 결과 | 가설 1 판정 | 다음 |
|---|---|---|
| S1·S2·S3 모두 충족 | 지지됨. 분모가 원인이고 띠도 복구 | 해당 변형으로 P=10 확장 |
| S1·S2 충족, S3 불충족 | 부분 지지. 포화는 분모 탓, 띠는 이 측정으로는 안 보임 | 띠가 없다는 결론은 이 궤적에 한정해 기록, 가설 3 쪽으로 |
| S1 불충족(세 변형 모두) | 기각(이 궤적, 이 변형 범위에서) | 가설 2·3, 3봉 재현 포기 후 E3′ 분류기로 |

## 4. 항상 보고하는 것

- 회귀 확인: 이번 재생의 변형 0~3이 `replay_variants.pt`의 같은 변형과 얼마나 다른지(최대 절대 차이, 레이어별 상관). MPS 비결정성 범위를 넘으면 결과를 해석하지 않고 원인부터 본다.
- 무거운 위치 수 `k(t)`의 길이 의존성: `paper`, `paper_nosink`에서 레이어 10의 `k`를 n 구간(0~500, 500~1500, 1500~3300)별 중앙값으로.
- `sink_mass`: 레이어별 평균과 스텝 상관.
- 변형별 `frac(sparsity > 0.98)` 전체 평균과 레이어 10 시계열 그림(MA128).

## 5. 알려진 한계와 선언

- 변형은 가설 1에서 직접 도출했다. 그림 3의 모양에 맞춰 고르지 않았고, 결과가 부정적이어도 새 변형을 사후에 추가해 같은 가설을 구제하지 않는다. 추가가 필요하면 별도 기록으로 새 가설로 등록한다.
- 3개 변형 × 32개 레이어를 보는 탐색이므로 우연히 기준을 넘는 레이어가 생길 수 있다. 임계 레이어 수(S1: 8, S3: 4)로 그것을 막는다.
- 궤적 하나(Llama-8B, 3301스텝)다. 결과가 이 궤적의 길이 범위(n ≤ 3.4k)를 넘어서는 주장은 하지 않는다.
- 논문 그림 3이 원자료가 아닐 가능성(가설 3)이 남아 있어, 그림 3의 수준값 자체를 목표로 삼지 않는다. 판정은 S1~S3로만 한다.

## 읽는 법의 주의 (기준은 바꾸지 않음)

- **창 변형의 S2 충족은 구조상 거의 보장된다.** n > W이면 분모가 W로 고정이라 길이 의존이 설계에서 제거된다. S2는 창 변형에 대해 독립된 검증이 못 된다. 길이 의존이 남는지 보는 깨끗한 시험은 `paper_nosink`이고, 거기서는 S2가 **불충족**이다.
- 사전 기준에서 S2가 창 변형에 대해 사실상 자명하다는 점을 기준을 정할 때 놓쳤다.

## 보고 항목 (§4)

- **무거운 위치 수 k = (1−s)·m, 레이어 10, n 구간 [0,500) / [500,1500) / [1500,3301) (n 중앙값 382 / 1132 / 2532)**
  - `paper`: 31.9 / 40.1 / 40.7. 길이가 6.6배가 돼도 k는 거의 그대로다.
  - `paper_nosink`: 158 / 155 / 198. 같은 모양이다.
  - `paper_win256`(m=256): 121 / 106 / 86. `paper_win1024`: 31.9 / 96 / 133.
  - 즉 행 전체를 쓰는 변형에서는 1%를 넘는 위치 수가 길이와 무관하게 거의 일정하다. 그래서 `1 − k/n`처럼 희소도가 길이와 함께 오른다(가설 1의 희석 메커니즘과 일치).
- **`sink_mass`**: 전체 평균 0.612, 레이어 10 평균 0.492(스텝 상관 −0.36), 레이어별 평균 0.191~0.868. 첫 토큰이 어텐션의 절반 가까이를 받는다.
- **자연 실험(그림 `all_layers_ma128.png`, 육안, 근사)**: `paper_win1024`는 n이 1024를 넘는 스텝 ≈ 890 부근에서 창이 위치 0을 잃으며 희소도가 약 0.96에서 0.82로 급락한다. `paper_win256`도 n ≈ 256 부근(스텝 ≈ 125)에서 약 0.9에서 0.4로 급락한다. 첫 토큰이 행에서 빠지는 순간에 맞춰 떨어진다.
- 레이어 10 `paper_nosink`: 스텝 상관 +0.33. 전 레이어에서 MA가 0.35~0.55에서 0.9 근처로 계속 올라간다(포화는 풀렸으나 길이 의존 잔존).
- `paper_win256`의 전 레이어 MA는 수백 스텝 간격으로 같이 오르내린다(육안). 띠 구조는 아니다(폭 중앙값 0.173).

## 결론 (이 궤적, 이 변형에 한정)

1. **포화의 원인은 확인됐다.** 어텐션 싱크가 행 최댓값을 정하고 무거운 위치 수는 길이와 무관하게 일정하다. 첫 토큰을 빼면 포화 비율이 0.82에서 0.10으로, 창으로 자르면 0.00~0.03으로 떨어진다. 가설 1의 "싱크 + 길이 희석"은 지지된다.
2. **그러나 논문 그림 3의 신호는 복구되지 않았다.** 3봉 레이어 0개, MA 폭 0.07~0.17(그림 3a는 눈금상 0.45 이상). 싱크를 제거해도 띠는 생기지 않았다.
3. 이 한 궤적(n ≤ 3.4k)으로는 더 긴 컨텍스트(논문 그림 3a는 약 10.8k스텝)에서 어떨지 모른다.

# 2단계 사전 기록 — 긴 궤적 (작성: 2026-11-04, 이 궤적의 결과를 보기 전)

- 이유: 위 결과는 n ≤ 3.4k 한 궤적이었다. 논문 그림 3a는 약 10.8k스텝이다. 길이 범위를 넓혀 같은 가설을 다시 본다. 방법은 희소도 측정만 쓴다(키워드·텍스트 기반 분류는 이번 단계에 쓰지 않는다).
- 대상: `aime_llama8b_p10_max35000/0000.pt` (AIME 2024 #70, 생성 10,569토큰 → 희소도 10,568스텝, 입력 91토큰). 그림 3a와 길이가 가장 비슷하다.
- 변형, 임계값, 판정 기준(S1~S3), `min_step=1100`은 위 §2~§3과 **동일하다. 바꾸지 않는다.** 스크립트도 같은 것을 쓴다(`replay_sparsity_v2.py`).
- 보고 항목만 하나 추가한다: 무거운 위치 수 k의 구간에 `[3300, T)`를 더한다(길이 범위가 늘어서). 판정에는 영향이 없다.
- 해석 규칙(판정 변경이 아님): 창 변형의 S2는 구조상 자명하므로(위 결과 기록 참조), 길이 의존이 남는지는 `paper_nosink`의 S2·k 추세를 따로 적는다.
- 판정은 사전 표를 이 궤적에 그대로 적용한다. 두 궤적(0005, 0000)의 결과가 갈리면 갈린다고 적는다. 합치지 않는다.
- 다음 단계 규칙:
  - S1·S2·S3 충족 변형이 있으면 → 그 변형으로 나머지 궤적(0001~0004, 0006~0009)을 재생하고 논문의 교집합 규칙과 50% 규칙을 둘 다 적용한다.
  - S3 불충족이면 → "분모를 고치면 포화는 풀리지만 3봉은 나오지 않는다"를 두 궤적에 대해 기록하고, 다음 방향은 사용자가 정한다.

## 무엇을 바꿨나

| | 구 S3 | **개정 S3 (이 시점 이후의 기준)** |

# 백로그 추가 — 봉우리 수가 같은 레이어 집합으로 유형 수 k를 정하기 (사용자 의견, 2026-11-04, P=9 시각화 확인 후)

확정이 아닌 의견·계획이다. 기준 변경이 아니며, 착수할 때 사전 기록을 먼저 남긴다. 시점은 논문 구현 한 바퀴(분류기 → TBE → TBQ → 조립) 이후다.

- **지금 데이터로 본 첫 확인 (P=9, 현재 규칙: Scott ×1, prominence 없음):** 9개 문제 모두에서 봉우리 수가 같고 k ≥ 2인 레이어는 8개 조합(변형 4 × 워밍업 2) 어디에도 **없다.** 9개가 전부 같은 수인 레이어는 `win256`의 1봉짜리 4개(워밍업 전체)와 2개(앞 1100 제외)뿐이다. 7개 이상이 같은 k(≥2)인 경우는 `full_literal`(앞 1100 제외)의 레이어 4(7개 문제가 2봉) 하나뿐이다. 봉우리 수 중앙값이 `full_nosink` 8, `win1024` 6, `full_literal` 13이라 현재 규칙의 봉우리 수는 잔물결이 지배한다.

  4. 유형별 비트 수. 논문의 유형별 중요도 순서는 3유형을 전제로 한 것이므로 k가 다르면 순서와 할당을 따로 정하고, 같은 예산에서의 정확도로 검증한다(대조군: 무작위 라벨, 위치만 쓰는 분류기).

  2. 레이어: 시간에 따른 변동(128스텝 이동평균의 표준편차 등)이 가장 큰 4개. 논문의 |L*|=4를 참고한 **내 제안이며 검증하지 않았다.** 변동이 사고 전환이 아니라 글 위치에 따른 완만한 변화일 수 있다.
  3. 평균 구간: 128스텝(논문의 갱신 간격 τ=128)
  4. 임계값: 합친 분포의 33%/67% 분위수
  5. 합치는 범위: 가용한 모든 문제(현재 9개)
- **한계(중요):** 분포에 구조가 없어도 3개 유형이 **항상** 나온다. 따라서 이 임계값은 "사고 유형이 실제로 나뉜다"는 증거가 아니고 논문 재현도 아니다. 분류기가 글의 위치만 따라가는 위치 분류기가 될 위험이 있다.
- **평가 요건:** 같은 예산에서 무작위 라벨 분류기, 위치만 쓰는 분류기를 대조군으로 두고 정확도를 비교한다(위 "최종 평가에 넣을 대조군"). 희소도 유형이 대조군보다 낫지 않으면 그 결과로 판단한다.
- **문서화 원칙:** "논문 Algorithm 1: FAIL, 분위수 임계값: 대체 방법"으로 분리해 적는다.

# 모델 크기 가설 검토 (사용자 질문, 2026-11-04 — 세션 처음에도 같은 질문이 있었음)

- **지금까지의 근거:** 옛 정의(행 전체, 헤드별 평균)로 R1-Distill-Qwen-1.5B(s1K), Qwen-7B(s1K), Llama-8B(AIME) 모두 FAIL이었고(`calib/sparsity/record.md`), 1.5B에서 8B로 커질 때 개선 경향은 보이지 않았다. 논문 그림 3의 왼쪽 패널은 **R1-Distill-Llama-8B(AIME, 레이어 10)로 우리와 같은 모델**인데도 우리는 그 레이어에서 세 띠를 재현하지 못했다(옛 정의 10개 문제 전부 1봉, 논문 정의 재생에서도 포화).
- **한계:** 위 크기 비교는 모두 논문과 다른 옛 정의로 했다. 논문 정의(식 2~4)로 재 본 것은 Llama-8B 하나뿐이다. 논문 그림 3의 오른쪽 패널(R1-Distill-Llama-70B, LiveCodeBench, 레이어 4)은 돌려 본 적이 없다.
- **70B를 돌릴 때의 대략적 부담(실측 아님, 추정):** bf16 가중치 약 140GB라 80GB GPU 2장이 필요하고, 가중치 내려받기만 수십 분이며, 한 스트림 생성 속도는 한 자리수 tok/s로 예상된다. 문제 3개(약 4만 토큰)만 해도 수 시간이 걸릴 수 있다. LiveCodeBench 프롬프트도 따로 준비해야 한다.
- **결론(잠정):** 모델 크기가 원인일 가능성은 낮다고 보지만 배제하지는 못했다. 크기를 먼저 키우기보다 측정 정의와 KDE 폭의 차이를 확인하는 편이 싸다.

# 백로그 갱신 (2026-11-04): 2유형(k=2)·"봉우리 수가 같은 레이어" 항목

- `win256` 레이어 0의 2봉은 토큰 확인 결과 **숫자 토큰 대 기호·단어 토큰**의 차이였다(`docs/e3_paper_calibration_spec.md` "키워드 라벨 신호 검증 결과"). 사고 유형이 아니므로 이 레이어를 근거로 한 k=2 양자화는 **보류**한다. 다른 레이어에서 봉우리다운 구조는 남지 않았다.
- 분위수 임계값(33%/67%)은 파이프라인용 임시값으로만 쓰고, 키워드 라벨과의 분리 신호가 없으므로 "사고 유형 분류기"라고 부르지 않는다.
