## 3. kvpress 위 구현 구조 (제안)

- **분류기** `ThoughtClassifier`: 디코드 중 레이어 24의 `win256_mid@max1` 희소도를 스텝마다 재고(수집과 같은 어텐션 함수 교체 방식), 128스텝마다 블록 평균 → 라벨. 라벨 이력(구간 목록)을 보관.
- **TBQ** `ThoughtQuantizer`: 가짜 양자화. 각 레이어의 KV 캐시에서 새로 찬 그룹(16토큰)을 현재 라벨의 비트로 양자화→역양자화해 제자리 덮어쓰기. 캐시 텐서는 bf16 그대로(정확도 효과만 재현).
- **TBE** `ThoughtEvictor`: 갱신 시점마다 경우 1·2 적용. 구간 테이블(시작·끝 위치, 유형, 보존 단계)을 레이어별 유지. 퇴출은 kvpress의 인덱스 선택 방식으로 K·V를 실제로 줄임(압축 효과는 토큰 수로 측정).
- **조립**: `DecodingPress`처럼 생성 루프의 훅으로 동작. 기존 `eval/baseline.py` 경로를 재사용해 AIME로 채점.
- **측정**: 정확도, 생성 길이, 스텝당 평균 KV 토큰 수(퇴출), 평균 비트 수(양자화), 처리량(참고).

## 4. 순서

1. 분류기 + TBQ(가짜 양자화)만으로 AIME 30문제 → FullKV·균일 4비트·균일 2비트와 비교.
2. TBE 추가(예산 1024) → 대조군 포함 전체 비교.
3. 결과 기록·판정(E4~E6).

## 5. 논문 재확인 정정 (2026-11-04, 사용자 "논문과 최대한 같게")

위 1·2절의 표에서 다음을 바로잡는다(본문 §4.2, §6.1, 표 1, E.2 재독).
- **정밀도 할당:** §4.2 방법 설명은 **R = 8비트(FP8, per-tensor FP32 스케일), E = 4비트(NVFP4), T = 2비트(Ternary)**, B = {2, 4, 8}, ρ(R)=2, ρ(E)=1, ρ(T)=0. §6.1 실험 설정은 "R·E 4비트, T 2비트"(§4.2도 "R은 4비트로도 손실 없음"이라 적음). 표 1의 ThinKV 평균 비트 수 3.4~3.5는 실험 설정 기준. → 결정 항목으로 올림(14번).
- **키/값 양자화 축:** "Following KIVI, **keys are quantized per-channel while values are quantized per-token**", 그룹 g = 16, FP8(E4M3) 공유 스케일. 즉 키는 채널마다 토큰 16개 묶음(시퀀스 축), 값은 토큰 안에서 채널 묶음. 2절 4번의 (a)가 논문과 일치.
- **평가 설정(E.2):** A100 80GB, **최대 생성 길이 32K**(Cai et al. 따름), **문제당 8회 생성해 pass@1 평균**. 2절 11번에 반영(비용 때문에 1회 생성 안을 병기).
- **기준선(§6.1):** 퇴출 H2O, RaaS, R-KV, LazyEviction; 양자화 KIVI, PM-KVQ; E.16에 SnapKV 결합. kvpress에 있는 것은 SnapKV·H2O류(ObservedAttention)·StreamingLLM·TOVA·Knorm, KIVI식 균일 양자화는 가짜 양자화로 재현 가능. R-KV·RaaS·LazyEviction·PM-KVQ는 없음. 2절 12번에 "논문 기준선에 가장 가까운 묶음"을 추가.
- **예산:** 주 비교 k = 1024(표 1 "ThinKV (k=1024)"), 처리량 표 3은 2048. 결정 항목 15번.
- **갱신 측정:** D.5 의사코드는 `i % τ == 0`일 때 `measure_sparsity(l)` 한 스텝, 레이어별 `thought[l]`; §4.1은 L* 평균 하나. 둘 다 논문. 2절 1·2번에 "논문" 표시.
- 결정 페이지: https://claude.ai/artifact/Gu6M9wDuwoQQencDpUc4xY (항목 15개, "논문" 표시 = 논문에 가장 가까운 선택, "제안" = 내 기본값, 미명시 항목은 따로 표시).
