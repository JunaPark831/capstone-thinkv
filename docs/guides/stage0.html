ThinKV 0단계 — 환경과 FullKV 기준선

캡스톤디자인 v2 · 기준 문서: ThinKV 구현 계획, kvpress 조사 노트 · 작성 2026-09-30

0단계 목표
  1. 이 Mac(M5 Pro, 48GB)에서 kvpress 환경을 만든다.
  2. 압축 없는 기준 결과(FullKV)를 MATH-500 몇 문제로 뽑는다.
  3. kvpress의 디코드 압축이 Mac(MPS)에서 실제로 걸리는지 확인한다.

여기서 잰 토큰/초가 GPU 서버를 언제, 얼마나 빌릴지 정하는 근거가 된다.

1환경 만들기

Mac의 기본 파이썬이 3.14라서 torch 호환이 불안하다. uv로 3.12 환경을 따로 만든다. 폴더 구조는 구현 계획 §5를 따른다.

mkdir -p ~/dev/thinkv-kvpress && cd ~/dev/thinkv-kvpress
git init
uv venv --python 3.12 .venv-kvpress
source .venv-kvpress/bin/activate
uv pip install kvpress scipy matplotlib
python -c "import torch, transformers, kvpress; print(torch.__version__, transformers.__version__, torch.backends.mps.is_available())"

마지막 줄에서 확인할 것:

  • mps 값이 True여야 한다.
  • transformers가 4.56 이상 5.3 미만이어야 한다. kvpress가 이 범위로 고정하고 층별 캐시 API(cache.layers[i].keys)를 직접 만지기 때문이다.

모델은 deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B. bf16 기준 약 3.5GB이고 처음 로드할 때 자동으로 받아진다.

2FullKV 기준 결과 — eval/baseline.py

kvpress의 pipeline은 쓰지 않는다. 기본값이 그리디 디코딩에 max_new_tokens=50이라 추론 모델 평가에 맞지 않는다. model.generate를 직접 부른다.

스크립트가 할 일:

  1. 모델을 dtype=torch.bfloat16으로 로드하고 (transformers 4.56부터 torch_dtype 대신 dtype) .to("mps")로 올린다.
  2. 데이터는 MATH-500. kvpress 평가 레지스트리가 쓰는 alessiodevoto/math500을 datasets로 받는다.
  3. 프롬프트는 R1-Distill 권장 형식. 시스템 프롬프트 없이, 문제 뒤에 Please reason step by step, and put your final answer within \boxed{}.를 붙이고 tokenizer.apply_chat_template(..., add_generation_prompt=True)로 감싼다.
  4. 샘플링은 do_sample=True, temperature=0.6, top_p=0.95. 계획서 E0 설정과 같다.
  5. max_new_tokens는 로컬에서 8000. 본 실험은 16k지만 Mac에서는 너무 오래 걸린다.
  6. 출력에서 마지막 \boxed{...}를 뽑아 정답과 비교한다. 괄호가 중첩될 수 있으니 정규식 말고 중괄호 개수를 세서 추출한다.
  7. 문제마다 한 줄씩 JSONL로 저장한다.

저장 필드는 처음부터 이렇게 잡는다. 이후 모든 실험이 같은 형식을 쓴다.

{"id", "press": "none", "correct", "gen_len", "truncated", "seconds", "tok_per_s"}
필드왜 필요한가
gen_len생성 토큰 수. 양자화만 하면 생성이 길어지는 현상(Fig 10d, 최대 5.1배)을 보려면 이 기준선이 있어야 한다.
truncatedEOS 전에 max_new_tokens에 닿았는지. 잘린 문제는 오답과 구분해서 봐야 한다.
tok_per_sGPU 서버 결정의 근거.
먼저 1문제만. 끝까지 생성되고 \boxed{}가 추출되면 10문제로 늘린다.

3디코드 압축이 Mac에서 걸리는지 확인

같은 스크립트에 옵션을 하나 추가해, 같은 10문제를 kvpress 내장 압축으로 돌린다.

from kvpress import DecodingPress, KnormPress

press = DecodingPress(base_press=KnormPress(), compression_interval=512, target_size=1024)
with torch.no_grad(), press(model):
    out = model.generate(..., return_dict_in_generate=True)

확인할 것:

  • 캐시가 실제로 줄었는지. out.past_key_values.layers[0].keys.shape[2]를 출력한다. 1024~1535 사이면 정상이다. 512스텝마다 압축이 걸려 그 사이에서 톱니처럼 움직인다. 전체 생성 길이가 그대로 나오면 hook이 안 걸린 것이다.
  • FullKV와 비교. 정확도와 생성 길이를 나란히 놓는다. 이게 계획서 E1의 첫 점이다.

✓완료 기준

토큰/초로 판단하는 법: 예를 들어 초당 20토큰이면 8000토큰 한 문제에 약 7분이다. 그러면 10문제 개발용으로는 Mac이 충분하지만, 본 평가(MATH-500 × 8샘플 × 시드 3, 16k)는 불가능하다는 게 숫자로 나온다. 그 숫자를 들고 GPU 서버를 알아본다.

!막히기 쉬운 곳

  • MPS에서 bf16 오류가 나면 torch.float32로 바꾼다(약 7GB, 48GB에 충분). float16은 Qwen2 계열에서 값이 넘쳐 NaN이나 이상한 출력이 나올 수 있어 피한다.
  • kvpress가 MPS에서 안 도는 경우. 단위 테스트는 CPU에서 돌고 일부 코드에 mps 분기도 있지만, 디코드 압축 전체가 MPS에서 도는지는 확인된 적이 없다. 에러가 나면 전체 메시지를 남겨둔다.
  • import kvpress만 해도 어텐션 함수가 전역으로 바뀐다. 0단계에서는 문제없지만, 1단계 캘리브레이션 스크립트에서는 kvpress를 import하지 않는다.
  • 한 with press(model) 안에서 여러 문제를 연달아 돌리면 DecodingPress의 버퍼·카운터가 이전 문제 것이 남는다. 문제마다 with를 새로 연다.
