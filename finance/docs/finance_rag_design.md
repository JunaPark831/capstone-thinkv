# 금융 응용 과업 설계: 미공개 합병 심의 + RAG (2026-11-23 초안)

근거: 2026-11-23 사용자와의 설계 대화. 보드 엔진은 `docs/ondevice_npu_cpu_design.md`를 따른다.
이 문서의 숫자 가운데 "추정"이라고 적은 것은 실측 전 값이다.

## 0. 목표와 범위

- **목표**: VENTUNO Q 위의 ThinKV(사고 유형별 KV 양자화·퇴출)를 실제 쓰임새에 얹어 보인다. 과제계획서의 "금융 에이전트 워크플로" 자리를 이 과업이 채운다.
- **과업**: 그룹 계열사 합병 건을 글로 쓴 검토 메모로 받아, 법령과 내부 규정을 찾아 적용하고, 합병가액부터 승인 판정까지 길게 추론한다.
- **보안 명분**: 합병 검토 사실, 대상 회사, 조건, 내부 심의 기준은 미공개 중요정보다. 외부는 물론 사내 다른 부서로부터도 막아야 하므로, 네트워크가 없는 보드 한 대가 정보 차단 벽이 된다.
- **범위 밖**: 여러 턴에 걸친 툴 호출(에이전트 방식), 프롬프트 KV의 압축, 실제 회사 자료 사용.

## 1. 결정 사항

| # | 항목 | 결정 | 근거 |
|---|---|---|---|
| 1 | 형태 | 프롬프트를 한 번 넣고 길게 추론한다. 검색과 프롬프트 조립은 파이썬이 정해진 순서로 한다 | 보드 엔진이 한 턴만 지원한다. 계획서에는 "고정 순서 워크플로"로 적는다 |
| 2 | 주제 | 미공개 계열사 합병 심의 | 사용자 결정("보안 명분이 우선"). 포트폴리오 스트레스 테스트와 DSR 대출 심사는 "클라우드 보안으로도 된다"는 반론에 약해 제외 |
| 3 | 모델 역할 | 모델이 직접 계산하고 판정한다. 파이썬은 채점용 정답만 계산한다 | 생각이 길어지고 숫자와 판정을 모두 채점할 수 있다 |
| 4 | 입력 형태 | 글로 쓴 검토 메모. 관련 없는 정보를 섞고, 해석이 필요한 상황을 심어 둔다 | 사용자 우려("파이썬으로 채점되면 모델이 필요 없지 않나")에 대한 답. 정리된 표가 아니라 글을 읽고 조항과 맞춰야 풀 수 있다 |
| 5 | 규칙 제공 | 같은 문제를 두 판으로 만든다. 규칙 명시판(필요한 조항을 프롬프트에 직접)과 RAG판(pgvector 검색) | 정확도 하락이 검색 탓인지 압축 탓인지 나눈다 |
| 6 | RAG 문서 | 법령 원문 3건 + 가상 내부 규정집 1건. 방해 문서는 넣지 않는다 | 사용자 결정 |
| 7 | 법령 판본 | 현행 조문(2026-11-13 시행본). 출처는 국가법령정보센터 원문만 | 2026-12-09 시행 개정법은 공식을 없애고 "공정한 가액"으로 바꿔 정답을 하나로 정할 수 없다 |
| 8 | 가상 회사 | 투팍 그룹 | 사용자 결정 |
| 9 | 퇴출 예산 | 질문마다 프롬프트 토큰 수 + 사고 몫(1024에서 시작) | `Plan`의 예산은 프롬프트를 포함한다. 고정값이면 긴 프롬프트에서 사고 구간이 전부 바닥까지 줄어든다 |
| 10 | 난이도 조절 | 규정을 전부 넣고 시작한다. 너무 어려우면 비상장사 평가부터 뺀다 | 사용자 결정 |

## 2. 전체 흐름

```
검토 메모(글) + 질문
  │
  ① 질문 임베딩            CPU, 임베딩 모델
  ② 조항 검색              pgvector, 상위 k개 (RAG판만)
  ③ 프롬프트 조립          메모 + 조항 + 질문 + 출력 형식
  ④ prefill               NPU(가중치) + CPU(어텐션). 프롬프트 KV는 모델 정밀도 그대로
  ⑤ 긴 추론               ThinKV: 구간별 사고 유형 판정, 4비트·2비트 저장, 예산 초과 시 퇴출
  ▼
심의 기록(JSON)
```

단계가 순서대로 돌아 임베딩 모델과 LLM이 CPU를 동시에 쓰지 않는다. RAG 층은 `ondevice/` 엔진 밖에 두고, 엔진에는 프롬프트와 예산만 넘긴다.

## 3. RAG 문서 (`finance/rag/`)

| 파일 | 성격 | 과업에서의 쓰임 |
|---|---|---|
| `자본시장법_시행령_제176조의5_합병가액.md` | 법령 원문 | 기준시가(세 종가의 산술평균), 10% 범위 조정, 보유 주식에 신주 배정 금지 |
| `증권발행공시규정_제5-13조_합병가액_산정기준.md` | 금융위 고시 원문 | 비상장사 평가를 시행세칙에 위임 |
| `증권발행공시규정_시행세칙_제4-8조_자산가치_수익가치_상대가치.md` | 금감원 세칙 원문 | 자산가치(순자산 조정 11가지), 자산가치와 수익가치의 1 대 1.5 가중 |
| `투팍그룹_합병투자심의기준_가상.md` | 가상 내부 규정 (28조 + 할인계수 표) | 조정률, 수익가치 계산, 빚 한도, 시너지 인정, 판정, 업종 예외, 계산 단위 |

**자르기**: 내부 규정은 조 단위, 법령은 항 단위로 자른다. 표는 쪼개지 않는다. 조각마다 문서 이름과 조항 번호를 붙인다.

**검색**: pgvector, 코사인 거리, 처음에는 인덱스 없이 전수 검색. 상위 k는 5에서 시작한다. 보드 prefill 속도가 실측되면 다시 정한다.

**임베딩 모델 후보**: `BAAI/bge-m3`, `nlpai-lab/KURE-v1`, `intfloat/multilingual-e5-small`. 7절의 검색 평가로 고른다.

## 4. 입력과 출력

**입력(검토 메모)**: 300~600토큰의 글. 두 회사의 주가 자료, 재무 숫자, 지분 관계, 합병 조건(현금 지급 비율, 차입 금리), 기대 효과와 그 근거, 통합 비용, 소송·보증 현황을 문장으로 적는다. 풀이에 쓰지 않는 정보(연혁, 임직원 수 등)도 섞는다.

**해석이 필요한 지점**(문제마다 0~4개를 심는다)

| 지점 | 메모에 적는 방식 | 맞춰 볼 조항 |
|---|---|---|
| 일회성 손익 | "지난해 영업손실에는 소송 비용 50억이 들어 있다" | 내부 규정 제7조 2항 |
| 근거 있는 기대 효과 | "물류 통합 절감 40억(견적서 확보)", "매출 증가 30억(내부 추정)" | 제19조 1항 |
| 우발채무 | "소송이 제기됨" 대 "1심 패소" | 제14조 3항 |
| 보유 지분과 자기주식 | "A는 B 지분 30%를 보유, B의 자기주식 10만 주" | 제18조, 시행령 7항 |
| 업종 예외 | 금융업, 바이오 | 제25조, 제26조 |

**출력**: 추론 과정 뒤에 내부 규정 제28조의 심의 기록을 JSON으로 낸다.

```json
{"합병가액_합병법인": 50100, "합병가액_피합병법인": 30900, "합병비율": 0.6168,
 "신주수": 1332288, "합병교부금_억": 166.86,
 "주당이익_1년차": 4911, "주당이익_2년차": 5145,
 "차입배수": 1.87, "이자보상배율": 8.0,
 "판정": "조건부 승인", "근거조항": ["제7조", "제19조", "제24조"]}
```

## 5. 문제 세트

문제 생성기가 숫자와 조건을 정리된 형태로 만들고, 거기서 메모(글)와 정답을 함께 낸다. 처음에는 30문제로 한다.

| 난이도 | 문제 수 | 내용 |
|---|---|---|
| 쉬움 | 10 | 상장사끼리의 합병. 조정률, 합병비율, 신주, 주당이익, 판정. 해석 지점 0~1개 |
| 보통 | 12 | 현금 지급, 기대 효과, 우발채무 포함. 해석 지점 2~3개 |
| 어려움 | 8 | 비상장사 평가(자산가치 조정, 수익가치 할인) 또는 업종 예외. 해석 지점 3~4개 |

네 가지 판정(반려, 경영위원회 회부, 조건부 승인, 승인)이 고르게 나오도록 숫자를 고른다. 문제마다 정답 조항 목록을 붙인다.

## 6. 채점과 측정

| 항목 | 방식 |
|---|---|
| 판정 | 네 가지 중 정확히 일치 (주 지표) |
| 합병가액, 합병비율, 신주 수 | 규정 제27조의 계산 단위대로 일치. 신주 수는 0.1% 오차 허용 |
| 주당이익, 배수 | 0.5% 오차 허용 |
| 근거 조항 | 정답 조항이 들어 있는 비율 |
| 형식 | JSON 파싱 성공 여부 |
| 완료 여부 | 생성 길이 상한에 걸렸는지, 답은 냈지만 틀렸는지를 나눠 적는다 |

함께 재는 것: 생성 토큰 수, 구간별 사고 유형 분포, KV 메모리(사고 KV 절감률과 전체 KV 절감률을 따로), 토큰당 속도.

## 7. 실험 순서

1. **시험 삼아 5문제**(GPU, 압축 없음): 모델이 한국어 메모를 읽고 풀 수 있는지, 생각이 얼마나 길게 나오는지 본다. 정답률이 너무 낮으면 결정 10에 따라 규정을 줄인다.
2. **검색 평가**: 문제마다 정답 조항이 상위 k개 안에 들어오는 비율을 임베딩 모델별로 잰다.
3. **GPU 본실험**: 30문제 × (압축 없음, ThinKV) × (규칙 명시판, RAG판) × 시드 3. 논문에 쓸 숫자는 여기서 나온다.
4. **보드 시연**: 3~5문제를 RAG 포함 전체 흐름으로 돌려 메모리, 속도를 잰다. 보드 실행은 보드 담당 팀원이 한다.

## 8. 위험과 미확인 가정

| # | 가정·위험 | 확인 방법 | 틀리면 |
|---|---|---|---|
| 1 | DeepSeek-R1-Distill-Llama-8B가 한국어 메모와 조문을 읽고 풀 수 있다 | 7절 1단계 | 문제와 규정을 영어로 옮기거나, 규정을 줄인다 |
| 2 | 사고 유형 경계값(수학 문제로 보정한 값)이 이 과업에서도 쓸 만하다 | GPU에서 유형 분포를 본다 | 이 과업으로 다시 보정한다 |
| 3 | 생각이 사고 몫(1024)보다 충분히 길게 나온다 | 7절 1단계의 생성 길이 | 퇴출 효과가 안 보이면 문제를 어렵게 하거나 사고 몫을 줄인다 |
| 4 | 산수 실수가 압축 탓인지 모델 실력 탓인지 구분된다 | 압축 없는 결과와 같은 시드로 비교 | 모델이 식만 쓰고 계산은 파이썬이 하는 방식으로 바꾼다 |
| 5 | 내부 규정에 모순이나 빠진 규칙이 없다 | 정답 계산기로 30문제를 돌린다. 지금은 예시 한 건만 손으로 풀어 봤다 | 조항을 고친다 |
| 6 | 보드에서 프롬프트 2,000토큰 안팎의 prefill이 감당된다 | 보드 실측 | 상위 k를 줄인다 |
| 7 | 16GB 안에 LLM, 임베딩 모델, Postgres가 함께 들어간다(추정: 가중치 약 5GB, 임베딩 약 1.1GB, Postgres 약 0.5GB) | 보드 실측 | 더 작은 임베딩 모델을 쓴다 |

## 9. 보안 설계

- 벡터 DB와 메모가 저장되는 디스크를 암호화한다. 임베딩에서 원문을 복원하는 공격이 알려져 있어 임베딩도 원문만큼 민감하다.
- 세션이 끝나면 KV 풀을 0으로 지운다. 지금 엔진은 퇴출된 칸을 지우지 않고 덮어쓸 때까지 둔다.
- 보드 Linux의 스왑을 끈다.
- 모델 가중치와 법령 문서는 USB나 한 방향 전송으로만 들여온다. 밖으로 나가는 것은 심의 기록뿐이다.

## 10. 코드 위치와 담당

- 새 디렉토리 `finance/`에 둔다. `ondevice/`, `kernels/`, `thinkv/`는 고치지 않고 불러다 쓴다.
- 만들 것: 문제 생성기와 정답 계산기, 메모 작성기, 문서 자르기와 pgvector 적재, 검색과 프롬프트 조립, 채점기.
- 코드를 어느 세션이 쓸지는 정하지 않았다.

## 11. 아직 정하지 않은 것

- 임베딩 모델 (7절 2단계 뒤)
- 사고 몫의 값 (7절 1단계 뒤)
- 생성 길이 상한
- 과제계획서의 "에이전트 워크플로" 문구를 "고정 순서 워크플로"로 고칠지
- 발표에서 법 조항을 인용할 때의 조문 재확인
