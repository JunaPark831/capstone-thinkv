# ondevice/ 인계 (2026-11-16, 설계 세션 thinkv-kvpress-b3 → 구현 세션)

## 맡는 일
VENTUNO Q 보드에 ThinKV를 올리는 코드. **NPU는 가중치 계산, CPU는 KV 캐시(진짜 양자화 저장·퇴출·빈칸 재사용)와 어텐션**을 맡는다.
스펙은 `docs/design/ondevice_npu_cpu_design.md` 하나다. 먼저 전부 읽는다.

## 규칙
- 코드는 **`ondevice/` 안에만** 쓴다. 테스트는 **`ondevice/tests/`**.
- **우리 범위는 모델과 코드 구현까지다.** 보드(VENTUNO Q)에 올려 돌리고 재는 일은 다른 팀원이 한다. 보드 실행을 전제로 사용자에게 로그를 요구하지 않는다.
- `kernels/`와 `thinkv/`는 **고치지 않고 불러다 쓴다**(다른 세션 담당). 가져다 쓸 파일·함수는 스펙 10절.
- 스펙과 다르게 가야 하면 코드를 먼저 바꾸지 말고 사용자에게 알린 뒤 스펙을 고친다. 스펙 수정은 설계 세션(thinkv-kvpress-b3) 몫이다.
- **M2부터는 구현 세션이 `ondevice/`에 직접 쓴다**(2026-11-19 변경. M1은 사용자가 직접 옮겨 적었다). 한 단계씩, 흐름 설명 → 코드 → 테스트 순서는 지킨다. 사용자가 쓴 `ventuno_quant.py`는 그대로 둔다.
- 사용자에게 설명할 때는 쉬운 말, 짧은 문단, 표.

## 사용자가 확정한 것 (다시 묻지 않는다)
1. NPU + CPU를 함께 쓴다. "전부 CPU" 경로는 대조군일 뿐이다.
2. 프롬프트 KV는 양자화도 퇴출도 하지 않는다(bf16 그대로).
3. 보드 결과가 GPU에서 잰 것과 달라도 된다. `FQ`·`ThinKVPress`와의 일치는 버그를 잡는 테스트로만 쓴다.
4. NPU 가중치 정밀도는 NPU가 요구하는 대로 따른다(벤더 기본 w4a16에서 시작).
6. **모델은 DeepSeek-R1-Distill-Llama-8B**(32층, 쿼리 헤드 32, KV 헤드 8, 헤드 차원 128). vast.ai GPU에서 돌린 것과 같다. Qwen3가 아니다. 층 수·헤드 수는 모델 설정에서 읽고 코드에 박지 않는다. Mac 테스트도 8B(bf16)만 쓴다(2026-11-19 결정).
5. 키 스케일은 묶음 전체가 퇴출될 때만 반납한다(A). 퇴출 때 재양자화(B)는 백로그 BL1이라 지금 만들지 않는다.

7. 2026-11-19에 세부 16개를 더 정했다(풀은 0에서 늘림, 조각 비교 기준은 logit 최대 차이 10 이하 등). 스펙 1.1절과 9절을 본다.

## 시작 순서 (스펙 6절)
Mac에서 할 수 있는 것부터 한 단계씩:
1. **M1 압축 저장**: 양자화 → 코드·스케일 → 풀기. 통과 기준은 풀어 낸 값이 `thinkv.quant.FQ[kind]` 출력과 비트 단위로 같은 것.
2. **M2 장부 연결**: 풀 두 개 + `BlockTable` + 묶음 번호. 어텐션은 "풀어서 PyTorch"로 임시 구현. 통과 기준은 `ThinKVPress`와 생성 토큰이 같은 것. 이때 **살아 있는 토큰당 키 스케일 바이트**를 재서 보고한다(스펙 R4).
3. **M3 융합 어텐션 커널**(C++/NEON).
4. **M3.5 모델 자르기**: 층 단위 NPU 조각을 PyTorch 모듈로 만들고, 조각 실행기를 갈아 끼울 수 있게 한다(Mac은 PyTorch, 보드는 NPU). 팀원용 실행·측정 안내도 쓴다.

M0·M4~M6(보드 실행·측정)은 **보드 담당 팀원 몫**이다. 우리가 넘기는 것은 Mac에서 검증된 코드, 조각으로 나눈 모델, 실행·측정 안내다.

## 환경
- 파이썬: `.venv-kvpress/bin/python`. 기존 테스트 실행 예: `.venv-kvpress/bin/python -m pytest tests/kernels -q`
- 브랜치: `e10-ct-kernel`. 커밋·푸시는 사용자가 시킬 때만.
- 설계 배경(Obsidian): Obsidian 볼트의 `version2/구현/ThinKV 구현 계획.md` §6

## 아직 모르는 것 (스펙 7절)
- R1: NPU 호출 왕복 지연(토큰당 33번). 팀원의 보드 실측 대기.
- R2: 조각을 NPU용으로 컴파일하는 도구(QAIRT 직접 / ExecuTorch Qualcomm 백엔드). 팀원 몫이다. 우리는 조각을 PyTorch 모듈로만 넘기고, 도구가 정해지면 내보내기를 붙인다(2026-11-19 결정).
- 스펙 8절의 시간·계산량 숫자는 전부 추정값이다.
